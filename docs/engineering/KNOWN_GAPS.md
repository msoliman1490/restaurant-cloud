# Restaurant Cloud — الفجوات المعروفة قبل الإطلاق التجريبي
## (Known Gaps Prior to Production Pilot)

**تاريخ التوثيق:** 8 نوفمبر 2026  
**الهدف:** توثيق المتطلبات الفنية والميدانية التي تفصل المرحلة الحالية عن مرحلة التشغيل الميداني التجريبي (Pilot Rollout).

---

## 1. تكامل الأجهزة الطرفية والمعدات (Hardware Peripherals)
- **طابعات الإيصالات الحرارية (ESC/POS Thermal Printers):**
  - **الوضع الحالي:** طبقة المحاكاة وأمر الطباعة في المتصفح جاهز.
  - **الفجوة المتبقية:** كتابة تعريفات أوامر الـ ESC/POS للطباعة المباشرة عبر الشبكة المحلية (Network Raw TCP / USB) لطابعات المطبخ (Kitchen Display / Kitchen Printer) مع دعم قص الورق الآلي والتنبيه الصوتي عند وصول طلب جديد.
- **قارئات بطاقات مدى وأجهزة الدفع (Payment Terminals):**
  - **الوضع الحالي:** توفير واجهات Provider Adapter لحفظ بيانات العملية والمعرف البنكي.
  - **الفجوة المتبقية:** الربط المباشر ببروتوكول Geidea أو NearPay أو POS Terminal عبر بروتوكول mada SPAN / IPP.

---

## 2. متطلبات هيئة الزكاة والضريبة والجمارك (ZATCA Phase 2 Official Clearance)
- **شهادات الأجهزة التشفيرية (Cryptographic Stamp Identifiers - CSID):**
  - **الوضع الحالي:** بنية الفاتورة المبسطة (B2C) وحساب الضريبة 15% وتوليد تمثيل الـ QR Code من الخادم جاهز.
  - **الفجوة المتبقية:** الحصول على شهادات الـ OTP الرسمية من بوابة "فاتورة" للكيان القانوني الحقيقي للعميل لتوليد شهادات الإنتاج (Production CSID) وتفعيل التوقيع الرقمي ECDSA وحساب الـ Invoice Hash والتسلسل المشفر (Cryptographic Chaining).

---

## 3. بيئة التحقق بخادم PostgreSQL 16 الحقيقي (Genuine Server Integration)
- **الوضع الحالي:** تم اجتياز 54 اختباراً مؤتمتاً محلياً بنسبة 100% على محرك PGlite تحت دور `rc_app_user` وسياسات RLS المفروضة، وتم إعداد مسار العمل المؤتمت `.github/workflows/gate1-ci.yml`.
- **الفجوة المتبقية:** ربط المستودع بـ GitHub وتشغيل المسار المؤتمت للتحقق ضد صورة الخادم الرسمية `postgres:16-alpine` لتوثيق ختم الاعتماد لـ Gate 1 رسميًا دون الاعتماد على PGlite فقط.

---

## 4. المزامنة الميدانية بين الخادم المحلي والسحابي (Branch Server Live Sync)
- **الوضع الحالي:** بنية `offlineQuotaLeases` وتحديد الحصص الموقعة لضمان عدم تجاوز المخزون في وضع عدم الاتصال جاهزة في قاعدة البيانات والـ Domain Kernel.
- **الفجوة المتبقية:** تشغيل عملية المزامنة الدورية الخلفية (Background Sync Service) بين `apps/branch-server` و `apps/api` عبر WebSockets أو HTTP Batch Sync عند انقطاع وعودة الاتصال بالإنترنت.

---

## 5. الخطوة التالية الموصى بها (Recommended Next Step)
1. ربط مستودع GitHub من قبل المالك وتشغيل مسار الـ CI للتحقق من تشغيل الاختبارات ضد خادم PostgreSQL 16 رسمي.
2. تزويد النظام ببيانات شهادة تجريبية لمطابقة الفواتير مع بيئة المحاكاة الرسمية لهيئة الزكاة (ZATCA Sandbox).
3. ربط خادم الفرع `apps/branch-server` لمزامنة المبيعات اللحظية.
